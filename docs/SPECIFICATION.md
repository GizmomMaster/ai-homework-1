# Спецификация проекта ai-homework-1

## 1. Назначение

Консольная утилита на Node.js для сканирования Markdown-файлов в заданной папке, извлечения всех содержащихся в них ссылок и проверки их доступности с формированием отчёта в консоли.

## 2. Технический стек

- Только Node.js (без сторонних фреймворков/зависимостей, если не оговорено иное).

## 3. Входные данные

- Папка для сканирования: `ai-homeworks/ai-homework-1/ecto-1-kb-main`.
- В папке рекурсивно ищутся все файлы с расширением `.md`.

## 4. Функциональные требования

### 4.1 Поиск файлов
Найти все `.md`-файлы в указанной папке (рекурсивно, по всем вложенным подпапкам).

### 4.2 Извлечение ссылок
Из каждого найденного файла извлечь все ссылки, встречающиеся в тексте:
- текстовые ссылки (например, markdown-синтаксис `[текст](ссылка)`);
- URL-адреса (внешние http/https-ссылки);
- полные и относительные пути на другие файлы (в т.ч. другие `.md`-файлы или иные ресурсы).

Для каждой найденной ссылки необходимо сохранять путь к файлу, в котором она обнаружена — это требуется для корректного разрешения относительных путей (см. п. 5.2).

### 4.3 Проверка ссылок
- **Локальные ссылки** (относительные и абсолютные пути к файлам): проверяется существование файла на диске.
- **Внешние HTTP(S)-ссылки**: проверяется доступность запросом.
  - Сначала отправляется `HEAD`-запрос.
  - Если ответа нет (или запрос не поддерживается сервером/завершился ошибкой), отправляется `GET`-запрос.

### 4.4 Вывод отчёта
- Отчёт выводится в консоль в виде таблицы со списком всех ссылок и их статус-кодами / статусом проверки.
- Успешные ссылки помечаются зелёным цветом.
- Сломанные ссылки помечаются красным цветом.
- Предусмотреть режим запуска, при котором в отчёт выводятся только сломанные ссылки (флаг/параметр запуска, см. `npm run start:broken`).

### 4.5 Документация
Сформировать `README.md` с инструкцией по запуску проекта (установка зависимостей, команды запуска, режимы работы).

## 5. Дополнительные условия и бизнес-правила

### 5.1 Таймауты HTTP-запросов
Таймаут по HTTP-запросам — 30 секунд. Если за это время ответ не получен, ссылка считается сломанной.

### 5.2 Критерии "сломанной" ссылки
- HTTP-ссылка: коды ответа `4xx` и `5xx` считаются неуспешными → ссылка сломана.
- HTTP-ссылка: отсутствие ответа в течение таймаута (30 сек) → ссылка сломана.
- Локальная ссылка: отсутствие файла по указанному пути → ссылка сломана.

### 5.3 Разрешение относительных путей
Относительные пути к файлам разрешаются относительно расположения файла, в котором была найдена ссылка (а не относительно корня сканируемой папки или рабочей директории процесса). Поэтому для каждой ссылки необходимо хранить путь к файлу-источнику.
